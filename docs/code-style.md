# Code Style

本文件记录当前项目更推荐的代码风格与组织方式。

它不是“绝对法典”，但新增代码应尽量向这里靠拢。

## 总体风格

项目偏好：

- 简洁直接
- 类型明确
- 结构清楚
- 渐进式重构

不鼓励：

- 为抽象而抽象
- 过度封装
- 一眼看不懂的“聪明写法”

## TypeScript

### 推荐

- 优先显式类型，特别是共享结构、props、返回值
- 公共对象结构优先定义接口或类型
- 异步函数尽量标明返回值
- 对错误分支给出明确 fallback

### 不推荐

- 大量使用 `any`
- 把多个不同含义的结构混在一个宽泛对象里
- 用类型断言掩盖真实问题

## React

### 组件拆分原则

组件拆分优先按职责和变化边界，而不是按 JSX 体积机械拆分。

更推荐拆分的情况：

- 一块 UI 语义独立
- 这一块会单独演进
- 这一块 props 边界清楚
- 主组件已经因为 JSX 过长影响阅读

不一定要拆的情况：

- 只使用一次且非常短
- 和父组件上下文强耦合
- 拆出去后反而让 props 过多

### 状态管理

推荐：

- 页面级状态留在页面组件
- 局部展示状态尽量贴近使用处
- 可复用副作用逻辑再抽 hook

不推荐：

- 很早就把所有状态抽进一个巨型 hook
- 为了“干净”把简单状态拆得四分五裂

### 事件处理

推荐命名：

- `handleSaveSettings`
- `handleRefreshApifox`
- `toggleRequest`
- `clearSelection`

命名应直接表达动作，不要过度缩写。

## 文件组织

### 推荐结构

对于页面型模块，优先使用类似结构：

```text
popup/
  Popup.tsx
  components/
  hooks/
  services/
  utils/
  constants.ts
  types.ts
```

### 放置规则

- 共享业务逻辑：`src/lib/`
- 页面专属展示：页面目录下的 `components/`
- 页面专属工具：页面目录下的 `utils/`
- 页面专属通信：页面目录下的 `services/`
- 页面专属默认值和轻量类型：页面目录下的 `constants.ts` / `types.ts`

## 命名风格

### 文件名

- React 组件：`PascalCase.tsx`
- 工具、hooks、service、常量文件：`kebab-case.ts` 或语义清晰的普通命名

### 变量名

- 布尔值优先使用可读命名，如 `loading`、`copying`、`showSettings`
- 表单输入状态建议带上输入语义，如 `apifoxExportUrlInput`
- 下一个状态值建议用 `nextXxx`

## 函数设计

### 推荐

- 一个函数聚焦一个职责
- 纯函数优先纯函数
- 复杂分支应有清晰的错误信息

### 不推荐

- 一个函数同时处理 UI、通信、格式化和存储
- 在多个地方复制粘贴几乎相同的分支逻辑

## 错误处理

推荐：

- 提供用户能理解的中文错误信息
- 同时保留足够定位问题的上下文
- 对已知兼容分支显式处理

例如：

- background 不支持某消息类型时，给出明确提示
- 加载当前 tab 失败时，告诉用户应在普通网页中打开插件

## 文案规范

项目当前面向中文使用场景，因此：

- UI 文案优先中文
- 状态文案优先完整句子
- 用户操作反馈尽量具体

推荐：

- `正在读取当前页面请求记录...`
- `复制成功，已写入 3 条接口信息。`

不推荐：

- `处理中`
- `成功`
- `失败`

## 样式与 UI

当前 popup 已有自己的视觉风格，因此修改现有 UI 时优先：

- 延续已有类名结构
- 延续当前色彩和反馈语气
- 优先局部增量调整

不要轻易把当前页面整体改造成另一种完全不同的设计体系，除非用户明确要求。

## Chrome Extension 代码约束

### runtime message

涉及消息通信时应尽量做到：

- 请求类型可枚举
- 响应结构清楚
- 调用方和处理方同步维护

### storage

涉及设置存储时应尽量做到：

- 有默认值
- 有兼容旧值的兜底
- 表单态和存储态分离

### 性能

popup 是高频入口，避免：

- 在打开时做重计算
- 在首屏同步等待大对象处理
- 把缓存构建逻辑塞到 UI 线程主路径

## 当前项目的具体建议

### 1. `src/lib/quick-copy.ts`

适合继续承载：

- 共享类型
- 纯工具函数
- 设置默认值和存储读写
- 复制文本拼装

但不适合继续膨胀成：

- popup 视图实现文件
- background 的事件监听聚合文件

### 2. `src/pages/popup`

推荐持续保持：

- `Popup.tsx` 负责页面编排
- 组件负责展示
- service 负责消息通信
- util 负责表单和轻量转换

### 3. `src/pages/background`

改动这里时优先小步进行，不建议顺手做大规模样式化重构。

## 文档风格

项目文档更推荐：

- 先背景，再问题，再方案
- 结论清楚
- 语言直接
- 面向后续维护者

这也适用于 AI 输出的设计说明和重构记录。
