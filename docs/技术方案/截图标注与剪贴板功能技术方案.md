# Quick Copy Ext 截图标注与剪贴板功能技术方案

> **更新时间**：2026-07-24；**使用模型**：GPT-5；**用户**：Jsmond2016

---

## 设计结论

首期采用 Chrome 专属的“后台捕获 + 内容脚本页面覆盖编辑器 + 活动页面 Clipboard 写入”架构：`chrome.tabs.captureVisibleTab` 先获取未含 UI 的当前视口 PNG；内容脚本在其后展示标注编辑器；用户点击完成时由当前已聚焦页面调用 `navigator.clipboard.write`。

该设计与录制功能分离：截图是一次性会话，不使用 `RecordingSession`、录屏预览 IndexedDB 或下载目录配置。截图也不要求页面处于接口监听 Origin 内，只要求当前标签页可被 Chrome 的 `activeTab` 授权访问。

## 架构与数据流

```text
Popup 点击 / 页面右键 / chrome.commands.onCommand
  -> Background 校验活动 HTTP(S) 标签页与截图会话状态
  -> chrome.tabs.captureVisibleTab(windowId, { format: 'png' })
  -> Content Script 收到 quick-copy/open-screenshot-editor(dataUrl, sessionId)
  -> 页面覆盖层：Canvas 渲染原图、裁剪和标注

用户点击“完成并复制”
  -> Canvas 合成：裁剪原图 + 标注层，导出 PNG data URL
  -> 当前内容脚本将 PNG data URL 同步转换为 Blob
  -> navigator.clipboard.write(ClipboardItem({ 'image/png': blob }))
  -> 返回成功/失败
  -> Content Script 关闭覆盖层并显示状态提示
```

截图必须先捕获、后注入编辑器。这能确保导出原图不包含遮罩、裁剪框、工具栏或标注操作过程。编辑器仅在页面顶部覆盖显示，原站点 DOM 和样式不应被修改。

## 技术选型

| 模块 | 选型 | 原因 |
|:---|:---|:---|
| 当前视口捕获 | `chrome.tabs.captureVisibleTab` | 原生返回 PNG data URL，适合用户显式触发的当前活动标签页。 |
| 页面编辑器 | 内容脚本 + `HTMLCanvasElement` | 保留上下文，渲染和坐标映射直接，避免引入体积较大的图形库。 |
| 标注模型 | Typed command/shape 数组 | 可实现选择、移动、删除以及有限历史的撤销/重做。 |
| PNG 合成 | 双 Canvas（base + annotation） | 导出前以裁剪矩形进行 `drawImage`，保证输出范围和质量可控。 |
| 图片剪贴板 | 当前页面内容脚本 + `ClipboardItem` | 在用户点击“完成并复制”的焦点与用户手势中写入 `image/png`。 |
| 会话状态 | Background 内存 Map | 截图不应跨重启恢复，不进入持久化存储。 |

不建议首期引入 Fabric.js、Konva 等画布框架。工具集和会话历史有限，原生 Canvas 能减少包体、扩展权限和长期维护面；当 P1 需要复杂对象变换、富文本和多页历史时再重新评估。

## 权限、构建与快捷键

Chrome 构建在现有 `activeTab`、`contextMenus`、`scripting`、`offscreen` 基础上新增：

```json
{
  "permissions": ["clipboardWrite"],
  "commands": {
    "quick-copy/capture-screenshot": {
      "suggested_key": {
        "default": "Ctrl+1",
        "mac": "Alt+1"
      },
      "description": "截图并标注当前页面"
    }
  }
}
```

- `activeTab` 由 Popup action、上下文菜单或扩展命令等用户手势临时授予，因此不需要为截图新增广泛站点权限。
- `clipboardWrite` 用于向系统剪贴板写入 PNG，扩展不声明 `clipboardRead`。
- 不把该 command 设为全局快捷键；全局命令限制更多，且用户目标是操作当前浏览器页面。
- `Ctrl+1` 是常见浏览器标签切换快捷键，Chrome 是否将其交给扩展须通过真实构建验证。安装后调用 `chrome.commands.getAll()` 读取实际注册结果；若为空，在 Popup 显示可用替代键和 `chrome://extensions/shortcuts` 设置引导。若稳定冲突，产品回退为 `Ctrl+Shift+1`，但 macOS 仍优先验证 `Option+1`。
- `captureVisibleTab`、`chrome.offscreen` 和本方案中的消息协议先仅进入 `vite.config.chrome.ts` 的 Chrome 产物；Firefox 保持不暴露入口，避免伪支持。

## 数据模型与消息协议

### 领域模型

```typescript
type ScreenshotTool = 'crop' | 'rectangle' | 'arrow' | 'pen' | 'number' | 'text';
type ScreenshotColor = 'red' | 'orange' | 'yellow' | 'green' | 'blue' | 'black' | 'white';

interface ImageRect {
  x: number;
  y: number;
  width: number;
  height: number;
}

interface ShapeStyle {
  color: ScreenshotColor;
  lineWidth: 1 | 2 | 4 | 6;
}

interface RectangleShape extends ShapeStyle {
  id: string;
  type: 'rectangle';
  rect: ImageRect;
}

interface ArrowShape extends ShapeStyle {
  id: string;
  type: 'arrow';
  from: { x: number; y: number };
  to: { x: number; y: number };
}

interface PenShape extends ShapeStyle {
  id: string;
  type: 'pen';
  points: { x: number; y: number }[];
}

interface NumberShape extends ShapeStyle {
  id: string;
  type: 'number';
  value: number;
  point: { x: number; y: number };
}

interface TextShape extends ShapeStyle {
  id: string;
  type: 'text';
  text: string;
  point: { x: number; y: number };
}

type ScreenshotShape = RectangleShape | ArrowShape | PenShape | NumberShape | TextShape;

interface ScreenshotEditorState {
  sessionId: string;
  sourceSize: { width: number; height: number };
  crop: ImageRect;
  shapes: ScreenshotShape[];
  selectedShapeId?: string;
  activeTool: ScreenshotTool;
  style: ShapeStyle;
}
```

坐标始终保存为原始图片像素坐标，而不是 CSS 像素。Canvas 显示尺寸根据 `devicePixelRatio` 和可用视口缩放，鼠标坐标在入口处反算为图片坐标；这能避免 Retina 屏、浏览器缩放和窗口尺寸变化造成标注偏移。

### Runtime 消息

```typescript
type ScreenshotRuntimeRequest =
  | { type: 'quick-copy/start-screenshot'; tabId: number; source: 'popup' | 'context-menu' | 'command' }
  | { type: 'quick-copy/open-screenshot-editor'; sessionId: string; imageDataUrl: string }
  | { type: 'quick-copy/close-screenshot-editor'; sessionId: string };

type ScreenshotRuntimeResponse =
  | { ok: true; data: null }
  | { ok: false; error: string };
```

`start-screenshot` 只能由 Background 接收后执行 `captureVisibleTab`，且必须校验 `tabId` 是否为目标窗口的活动标签页。`open-screenshot-editor` 只允许 Background 发送；`close-screenshot-editor` 必须匹配当前有效 `sessionId`，防止旧页面或重复消息影响当前编辑会话。

Chrome 扩展消息以 JSON 序列化，不能直接假设 `Blob` 或 `ArrayBuffer` 会被结构化克隆。因此首期使用 PNG data URL 传输，并在执行前设置上限：原始截图任一边超过 `4096 px` 时，Background 使用 `OffscreenCanvas` 等比例压缩至上限后再发送。超过可接受消息大小或压缩失败时返回明确错误，不打开空编辑器。

## 关键实现细节

### 会话互斥与清理

- Background 维护单个 `activeScreenshotSession`，包含 `sessionId`、`tabId`、`windowId`、`status` 和创建时间。
- 新截图请求先向旧会话标签页发送关闭消息，再创建新会话。发送失败也必须清除旧状态。
- 监听 `tabs.onRemoved`、`tabs.onUpdated`（页面导航）和 `windows.onRemoved`，命中当前会话即关闭覆盖层并清理状态。
- 完成、取消、复制失败退出及异常都调用统一 `disposeSession`；不得持久化原图、标注或 data URL。

### Canvas 合成

1. 以原图尺寸建立导出 Canvas。
2. 按裁剪矩形创建目标 Canvas，并将原图的裁剪区域绘制为 `(0, 0)`。
3. 对标注 Canvas 设置与裁剪区域相反的平移，并使用 `clip()` 限制在目标 Canvas 内。
4. 按创建顺序绘制形状，在右下角绘制低透明度的 `icon-32.png` 与 `Quick Copy Ext` 水印，最后 `toBlob('image/png')` 并转换为 data URL。

文本编辑期间使用覆盖在 Canvas 上方的原生 `textarea`，确认后保存为 `TextShape`；不要尝试在 Canvas 内自行处理输入法组合文本。命中检测首期按形状包围盒和箭头线段容差实现，画笔按路径采样点判断。

### 剪贴板写入

编辑器在“完成并复制”的用户点击事件中直接写入图片剪贴板：

```typescript
const blob = dataUrlToPngBlob(imageDataUrl);
await navigator.clipboard.write([
  new ClipboardItem({ 'image/png': blob }),
]);
```

必须在 Blob 创建后立即调用 `navigator.clipboard.write`，不能等待跨上下文消息或异步资源加载，否则可能失去浏览器要求的用户激活与页面焦点。水印图标在编辑器打开时预加载，导出阶段不等待网络或图片加载。

## 风险与应对

| 风险 | 影响 | 应对 |
|:---|:---|:---|
| `Ctrl+1` 被浏览器标签切换占用 | 快捷键不可用或行为不一致 | 真实 Chrome 版本验证，读取实际注册快捷键，提供设置页改键；必要时改为 `Ctrl+Shift+1`。 |
| 高 DPI 截图数据过大 | 消息传输、Canvas 内存和复制失败 | 尺寸上限、等比压缩、单会话互斥、完成后立即释放 data URL。 |
| 不支持的特殊页面 | 捕获或脚本注入失败 | 仅允许 HTTP(S)，捕获/注入分别捕获错误并以用户可理解文案返回。 |
| 剪贴板被系统或权限策略拒绝 | 用户无法粘贴，可能丢失编辑结果 | 在活动页的用户点击链路写入 + `clipboardWrite`；失败时保留编辑器并支持重试。 |
| 页面 CSS 污染编辑器 | 工具栏错位或不可操作 | Shadow DOM 挂载、样式隔离、最高层级 z-index、捕获键盘与指针事件。 |
| 画布坐标错位 | 标记位置与页面不一致 | 所有数据使用图片像素坐标，集中处理缩放与 `devicePixelRatio`。 |

## 实施顺序与验证

| 序号 | 工作项 | 验收点 |
|:---:|:---|:---|
| 1 | 类型、Chrome manifest、命令和右键入口 | 三种入口均能请求后台截图，Firefox 无入口。 |
| 2 | Background 截图会话与内容脚本挂载 | 仅当前视口被捕获，编辑器不会出现在原图。 |
| 3 | Canvas 基础能力 | 裁剪、矩形、箭头、颜色、线宽可正确导出 PNG。 |
| 4 | 交互完善 | 画笔、数字、文本、选择移动、删除、撤销/重做可用。 |
| 5 | Offscreen 剪贴板与错误恢复 | 完成后可粘贴图片，失败后可重试且不丢编辑状态。 |
| 6 | 回归与发布资料 | `pnpm exec tsc --noEmit`、`pnpm build`、`pnpm build:firefox`；更新 Chrome Web Store 权限/隐私说明与功能截图。 |

手工测试应覆盖普通页面、Retina 屏和非 100% 页面缩放、含跨域 iframe 的页面、超大视口、录制进行中发起截图、快捷键冲突和剪贴板被拒绝等场景。现有 TypeScript 背景页定时器已知错误需与本次截图模块的报错分开判断。
