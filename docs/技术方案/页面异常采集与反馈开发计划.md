# 页面异常采集与反馈开发计划

> **编写时间**：2026-07-16；**使用模型**：GPT-5；**用户**：Jsmond2016

---

## 背景与目标

Quick Copy Ext 当前可以采集当前页面的接口请求和响应异常，但无法记录导致页面白屏、渲染中断或交互失效的前端运行异常。

本次改动的目标是：

1. 采集页面中未捕获的 JavaScript 异常、未处理的 Promise 异常和关键脚本加载失败。
2. 通过页面轻提示和扩展图标 Badge 及时告知测试人员。
3. 在 Popup 中持久展示页面异常，并支持复制包含 Web 页面、可能关联接口和错误日志的反馈文本。
4. 明确区分“页面异常”与“白屏”，不对异常根因做过度推断。

## 功能范围

### 包含

- `window.error` 中未捕获的运行时异常。
- `window.unhandledrejection` 中未处理的 Promise 异常。
- `<script>` 元素加载失败。
- 异常去重、数量限制、Tab 级会话缓存。
- 监听 Origin 过滤、页面提示、Badge 和 Popup 异常面板。
- 单条异常复制，以及异常发生时间附近的可能关联接口。

### 不包含

- 对所有白屏情况进行视觉或 DOM 启发式判定。
- 采集被 `try/catch` 或 React Error Boundary 完全消化的异常。
- 自动上传错误日志到远程服务。
- 自动判定某个接口是页面异常的根因。

## 方案设计

### 核心流程

```text
页面上下文 page-network-hook
  -> window.postMessage
Content Script
  -> chrome.runtime.sendMessage
Background Service Worker
  -> Origin 过滤 / 去重 / session 缓存 / Badge
Popup usePageErrors
  -> PageErrorPanel
  -> 复制标准化反馈文本
```

### 数据模型

```typescript
type PageErrorKind = 'runtime' | 'unhandledrejection' | 'resource';

interface CapturedPageErrorPayload {
  kind: PageErrorKind;
  message: string;
  name?: string;
  stack?: string;
  filename?: string;
  lineNumber?: number;
  columnNumber?: number;
  resourceUrl?: string;
  pageUrl: string;
  occurredAt: number;
}

interface PageErrorRecord extends CapturedPageErrorPayload {
  id: string;
  tabId: number;
}
```

单个 Tab 最多保留 20 条异常。相同类型、消息、文件位置和行列信息在短时间内视为重复异常。堆栈和消息进行长度限制，避免无界数据进入扩展缓存。

### Runtime 消息

| 消息 | 方向 | 用途 |
|:-----|:-----|:-----|
| `quick-copy/report-page-error` | Content -> Background | 上报页面异常，返回是否被监听配置接受 |
| `quick-copy/page-session-started` | Content -> Background | 新文档加载时清理同 Tab 的旧页面异常 |
| `quick-copy/open-popup` | Content -> Background | 用户点击页面提示时打开扩展详情 |
| `quick-copy/get-tab-page-errors` | Popup -> Background | 获取当前 Tab 的异常记录 |
| `quick-copy/clear-tab-page-errors` | Popup -> Background | 清空当前 Tab 的异常记录 |
| `quick-copy/page-errors-updated` | Background -> Popup | 通知 Popup 刷新异常记录 |

### 交互设计

1. 只有被 Background 确认为“已监听 Origin”的高价值异常才显示页面提示。
2. 页面提示使用 Shadow DOM 隔离样式，提供“复制错误信息”、“查看详情”和“关闭”操作。
3. 同一页面会话只主动提示一次，后续异常仍继续记录。
4. Background 为当前 Tab 设置红色 `!` Badge；Popup 读取记录后将其标记为已读。
5. Popup 中的“页面异常”面板位于“捕获接口历史”之前，默认展示摘要，堆栈按条目折叠。
6. 关联接口取异常发生前 10 秒至发生后 3 秒的请求，最多展示 3 条，统一标注为“可能关联接口”。

## 实施步骤

1. 扩展共享类型、常量、Runtime 消息联合类型和异常复制文本构建函数。
2. 将 Content Script 运行时机调整为 `document_start`，在页面脚本中注册异常监听。
3. Content Script 负责消息校验、Background 上报和 Shadow DOM 页面提示。
4. Background 增加 Tab 级异常缓存、去重、Badge 和 Runtime 消息处理。
5. Popup 增加 `usePageErrors` Hook、Runtime Service 和 `PageErrorPanel` 组件。
6. 增加异常面板和页面提示的样式，保持现有产品视觉风格。
7. 执行 TypeScript 检查、Chrome 构建和 Firefox 构建。

## 验收标准

- [ ] 监听 Origin 内发生未捕获异常时，页面可见一次轻提示。
- [ ] 未监听 Origin 不显示提示且不保存异常。
- [ ] 异常发生后扩展图标显示红色 `!` Badge。
- [ ] Popup 展示异常类型、消息、时间、位置、堆栈和可能关联接口。
- [ ] 页面提示和 Popup 均可复制可直接发给开发人员的错误信息。
- [ ] 重复异常不会在短时间内大量堆积，单 Tab 记录数不超过 20 条。
- [ ] 清空页面异常后面板和 Badge 状态同步更新。
- [ ] `pnpm exec tsc --noEmit`、`pnpm build:chrome` 和 `pnpm build:firefox` 未出现本次改动引入的错误。

## 风险与应对

| 风险 | 影响 | 应对方案 |
|:-----|:-----|:---------|
| 页面脚本早于钩子执行 | 可能遗漏最早期异常 | 使用 `document_start` 并在页面钩子最前面注册监听 |
| 跨域脚本错误信息受限 | 可能只得到 `Script error.` | 保留已知文件信息，在文档中明确该浏览器边界 |
| 页面样式污染扩展提示 | 提示不可见或布局异常 | 使用 Shadow DOM 和固定层级 |
| 异常循环产生大量数据 | 缓存和 Popup 性能下降 | 实施去重、截断和数量上限 |
| 时间窗口关联接口并非根因 | 测试人员可能误解 | 统一使用“可能关联”文案，不做因果结论 |
