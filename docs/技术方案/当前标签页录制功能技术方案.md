# Quick Copy Ext 当前标签页录制功能技术方案

> **更新时间**：2026-07-24；**使用模型**：GPT-5；**用户**：Jsmond2016

---

## 背景与目标

Quick Copy Ext 已能收集页面、接口和页面异常证据，但用户在提交缺陷时仍需手工补充复现过程。当前标签页录制用于保存用户复现异常时的页面动态过程，并作为反馈附件的本地证据。

首期目标是让用户从扩展 Popup 显式开始和停止录制当前标签页，在本地下载视频文件，并在复制反馈时提示已生成录屏附件。

## 范围与边界

### 包含

- 默认录制用户点击开始时的当前标签页；可选录制当前 Chrome 窗口，以覆盖同一窗口内的标签页切换和新打开的标签页。
- 无音频录制，输出 `WebM` 文件。
- 手动开始、手动停止、标签页关闭时自动停止。
- 录制状态、开始时间和最近一次保存的文件名在当前浏览器会话内保存。
- 最近一条录屏 Blob 保存在扩展同源 IndexedDB，供 Options 页面本地预览；新录制会替换旧预览。
- Popup 显示开始、录制中和已保存三个状态；Options 页面提供全尺寸预览与清除本地预览。
- Options 页面可配置录屏在浏览器下载目录下的存放子路径，默认 `quick-copy-ext`，通常对应 `~/Downloads/quick-copy-ext`。
- 复制反馈时写入录屏附件状态。

### 不包含

- 桌面、窗口、摄像头、麦克风和系统音频录制。
- 视频剪辑、转码为 MP4、云端上传和自动挂载到 AIO。
- 长期录制历史或跨浏览器同步。
- Firefox 的录制实现；Firefox 构建中应隐藏录制入口。

## 交互设计

1. 用户在被监听页面打开 Popup，或在页面空白处右键选择“Quick Copy：录制当前标签页”后立即开始录制。若需要覆盖同一窗口中新打开或切换的标签页，可选择“Quick Copy：录制当前窗口（含新标签页）”；扩展会打开独立的选择窗口，用户点击开始后在 Chrome 选择器中选中当前浏览器窗口。
2. 开始后页面右下角显示半透明、可透视页面内容的录制浮层，包含录制状态和累计时长；可拖动红点和状态区域调整位置，位置按页面 Origin 记忆。单一圆形控制按钮短按暂停/继续、按住时以环形进度表示 1.3 秒结束并保存，松手取消；扩展图标使用红色 `REC` Badge 表示录制中。
3. 用户可从浮层或 Popup 暂停、继续、停止录制；暂停不计入视频时长。
4. 停止后自动下载至 `~/Downloads/quick-copy-ext/quick-copy-recording_yyyyMMdd_HHmmss.webm`（或用户配置的下载目录子路径），Popup 显示“录屏已保存，请在缺陷平台上传附件”。
5. 用户在扩展 Options 页面查看最近一条录屏的全尺寸预览，或删除扩展内的预览副本；删除不会影响已下载的文件。
6. 后续复制反馈文本中的截图行替换为录屏附件状态；没有录屏时保持现有 `-`。

录制不绑定 Popup 生命周期。Popup 在用户返回业务页面时会关闭，持续媒体流由 Offscreen Document 持有。

## 架构设计

```text
Popup 点击开始或页面右键菜单（用户手势）
  -> chrome.tabCapture.getMediaStreamId(tabId)
  -> runtime message: start-recording(streamId, tabId)
  -> Background 创建 Offscreen Document 并保存会话状态
  -> Offscreen getUserMedia(streamId) + MediaRecorder（1080p / 24fps，支持 pause/resume）
  -> IndexedDB 保存最近一条 Blob 供 Options 预览
  -> runtime event: recording-updated
  -> Popup 与页面右下角浮层查询并展示状态

Popup 或页面浮层点击暂停/继续/停止
  -> runtime message: pause-recording / resume-recording / stop-recording(tabId)
  -> Offscreen MediaRecorder.pause() / resume() / stop()

停止后
  -> Offscreen 发送 Blob URL 和文件名
  -> Background chrome.downloads.download() 创建下载任务并保持“正在保存”
  -> chrome.downloads.onChanged 确认任务 complete 后释放 Blob URL
  -> runtime event: recording-updated
```

## 技术选型

| 模块 | 选型 | 原因 |
|:---|:---|:---|
| 默认标签页画面 | `chrome.tabCapture.getMediaStreamId` | 仅访问用户显式启动的当前标签页，不需要桌面选择器。 |
| 可选窗口画面 | `chrome.desktopCapture.chooseDesktopMedia` | 用户显式选择当前 Chrome 窗口，覆盖其中新打开和切换的标签页。 |
| 生命周期 | `chrome.offscreen` | MV3 Service Worker 与 Popup 都不适合长期持有 `MediaStream`。 |
| 编码 | `MediaRecorder` + `video/webm` | 浏览器原生能力，首期不引入转码依赖。 |
| 保存 | `chrome.downloads.download` | 文件直接落入用户浏览器下载目录，不需要扩展内持久化视频。 |
| 预览缓存 | IndexedDB（最近一条） | Options 页面与 Offscreen 同源，可预览而无需读取下载目录。 |
| 状态 | `chrome.storage.session` | Service Worker 重启后仍可恢复元信息，不写入同步配置。 |

## 数据与消息协议

```typescript
type RecordingStatus = 'idle' | 'recording' | 'paused' | 'saving' | 'saved' | 'error';

interface RecordingSession {
  status: RecordingStatus;
  tabId?: number;
  startedAt?: number;
  elapsedMs?: number;
  savedFileName?: string;
  recordingId?: string;
  error?: string;
}
```

新增 runtime message：

- `quick-copy/get-recording-session`：Popup 读取当前标签页会话。
- `quick-copy/get-latest-recording-session`：Options 页面读取最近录屏会话。
- `quick-copy/clear-recording-preview`：删除最近一条扩展内预览副本，不影响下载文件。
- `quick-copy/start-recording`：Popup 传入通过用户手势获得的 `streamId` 与 `tabId`。
- `quick-copy/pause-recording`、`quick-copy/resume-recording`、`quick-copy/stop-recording`：请求 Offscreen 暂停、继续或停止并保存。
- `quick-copy/recording-updated`：后台向 Popup 与当前页面浮层广播状态更新。
- `quick-copy/offscreen-recording-stopped`、`quick-copy/offscreen-recording-failed`：Offscreen 与后台的内部协作消息。

每个标签页最多允许一个会话；首期同一时刻只允许一个全局录制会话。第二次开始请求返回清晰错误，避免并发媒体流和下载文件互相覆盖。

## 权限与隐私

Chrome 构建新增 `desktopCapture`、`tabCapture`、`offscreen`、`downloads`、`contextMenus`、`unlimitedStorage` 权限。视频只在用户点击开始后采集，默认无音频；不上传远程服务、停止后直接下载到本地。`unlimitedStorage` 仅用于保留最近一条高质量录屏的本地预览副本。

录制目录配置保存在 `storage.sync`，值只能是下载目录下的相对路径；Chrome Extension API 不允许扩展写入任意绝对文件系统路径。

`tabCapture` 会使商店审核与用户权限提示更敏感。发布前必须同步更新 Chrome Web Store 与 Edge Add-ons 的权限说明、数据收集说明和功能截图。

## 风险与应对

| 风险 | 影响 | 应对 |
|:---|:---|:---|
| Popup 自动关闭 | 媒体流中断 | Offscreen Document 持有流和编码器。 |
| 用户不易感知录制状态 | 忘记停止或无法快速暂停 | 页面右下角常驻录制浮层、Badge 与右键菜单入口。 |
| 视频过大 | 内存、IndexedDB 与下载耗时上升 | 限制 5 分钟、1080p、24fps、约 6 Mbps；仅保留最近一条预览，超时自动停止。 |
| 用户遗漏录制状态 | 误录制敏感页面 | `REC` Badge、Popup 时长、标签页关闭自动停止。 |
| Badge 与页面异常冲突 | 状态不可见 | 录制时 `REC` 优先；停止后由页面异常逻辑恢复提示。 |
| Firefox API 不一致 | 构建或运行异常 | Firefox 构建不声明 Chrome 专属权限，Popup 通过能力检测隐藏入口。 |
| 下载失败 | 视频丢失或用户无感 | 监听下载任务终态；仅 `complete` 标记为已保存，`interrupted` 显示可重试原因并延后释放 Blob URL。 |

## 任务拆分与验收

| 序号 | 任务 | 产出 | 验收标准 |
|:---:|:---|:---|:---|
| 1 | Manifest 与类型 | 权限、会话类型、消息协议 | Chrome 类型检查通过，Firefox 不包含 Chrome 专属权限。 |
| 2 | Offscreen 录制器 | MediaStream、MediaRecorder、停止事件 | 可生成非空 WebM Blob，异常可上报。 |
| 3 | 后台会话服务 | 会话缓存、下载、标签页清理、Badge | 开始/停止状态可恢复，关闭标签页自动停止。 |
| 4 | Popup 控制 | 录制面板、状态订阅、用户提示 | 可开始/停止，时长实时更新，非监听页不可开始。 |
| 5 | 反馈关联与发布资料 | 复制文本、隐私/权限说明 | 已保存时文本包含附件提示，未保存时保持兼容。 |
| 6 | 验证 | TypeScript、Chrome/Firefox 构建、手工冒烟 | 两种构建通过，Chrome 可完整录制和下载。 |

## 验收场景

- [ ] 在已配置监听 Origin 的活动标签页开始录制，Popup 关闭后录制仍持续。
- [ ] 重新打开 Popup 可看到增长的录制时长，并可停止保存。
- [ ] 停止后浏览器下载目录出现可播放的非空 `.webm` 文件。
- [ ] 复制反馈文本显示“录屏：已保存，请在缺陷平台上传附件”。
- [ ] 标签页关闭、媒体流意外结束、下载失败时，录制状态不再停留在“录制中”。
- [ ] 未配置监听 Origin、非 HTTP(S) 页面或 Firefox 构建不展示可执行的开始录制操作。
