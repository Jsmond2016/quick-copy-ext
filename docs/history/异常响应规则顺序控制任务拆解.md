# 异常响应规则顺序控制任务拆解

> **编写时间**：2026-06-01；**修改时间**：2026-06-01；**使用模型**：GPT-5 Codex；**用户**：Jsmond2016

---

## 背景

基于《异常响应规则顺序控制技术方案》，本次改造需要将“异常响应规则”统一为“有序数组 + 首条命中即停”的模式。

本任务拆解文档用于指导实现、联调与评审，确保改动路径清晰、风险可控。

## 目标

本次任务需要达成以下目标：

1. 支持新版数组格式规则配置
2. 规则按数组顺序判断
3. 一个接口只命中第一条满足条件的规则
4. 取消额外控制字段，简化配置结构
5. 更新默认配置与设置面板提示
6. 完成基本验证并形成可评审结果

## 任务范围

本次主要涉及以下文件：

- `src/lib/quick-copy/response-rules.ts`
- `src/lib/quick-copy/constants.ts`
- `src/pages/popup/components/SettingsPanel.tsx`

可能受影响但无需大改的文件：

- `src/pages/popup/Popup.tsx`
- `src/pages/popup/utils/settings-form.ts`
- `src/lib/quick-copy/settings.ts`
- `src/pages/background/index.ts`

## 任务拆解

## 任务一：改造规则类型与解析逻辑

**目标**：让规则配置统一解析为有序数组结构。

**改动点**：

- 简化 `ResponseErrorRuleEntry` 类型，仅保留 `label` 与 `expression`
- 改造 `parseResponseErrorRuleConfig`
- 仅支持解析新版数组格式

**验收标准**：

- 新版数组格式可解析成功
- 非数组格式返回 `undefined`
- 非法数组项返回 `undefined`

## 任务二：改造规则命中顺序

**目标**：规则按用户书写顺序执行，且只命中第一条。

**改动点**：

- 重写 `getMatchedResponseErrorRules`
- 取消当前按 `conditionCount` 和 `index` 的排序逻辑
- 改为顺序遍历命中
- 首条命中后立即停止

**验收标准**：

- 命中结果顺序与配置顺序一致
- 首条命中后，后续规则不再命中
- 最终命中结果最多只有 1 条

## 任务三：改造配置校验

**目标**：确保设置保存和导入时，能正确校验新的数组格式。

**改动点**：

- 更新 `isValidResponseErrorRuleConfig`
- 校验字段：
  - `label` 非空
  - `expression` 非空
  - `expression` 可被表达式解析器识别

**验收标准**：

- popup 保存配置时，新数组格式可保存
- popup 导入配置时，新数组格式可导入
- 非数组格式会被拒绝并提示格式错误
- 非法数组项会被拒绝并提示格式错误

## 任务四：更新默认配置

**目标**：让新用户默认接触到新版规则格式。

**改动点**：

- 更新 `DEFAULT_RESPONSE_ERROR_RULE`
- 使用数组格式作为默认模板

**建议默认值**：

```json
[
  {
    "label": "接口异常",
    "expression": "res.rtn !== 0"
  }
]
```

**验收标准**：

- 重置配置后，异常响应规则显示新版数组模板
- 默认配置通过校验

## 任务五：更新设置面板文案

**目标**：让用户理解新的配置方式和顺序语义。

**改动点**：

- 更新 `SettingsPanel.tsx` 中的 placeholder
- 更新帮助文案

**文案重点**：

- 按书写顺序依次判断
- 一个接口只会命中第一条满足条件的规则
- 当前仅支持数组格式

**验收标准**：

- 设置面板显示新版示例
- 用户可仅根据面板提示理解配置方式

## 任务六：基础验证

**目标**：确认核心场景行为符合设计预期。

**验证场景**：

1. `403` 场景优先命中“无权限”，且不再继续命中“异常”
2. “下拉为空”与“列表为空”可按顺序互斥判断
3. 非数组格式会被拒绝保存
4. popup 保存、导入、重置后规则均能正常显示和校验

**建议验证方式**：

- 优先执行 `pnpm exec tsc --noEmit`
- 如无额外阻塞，再执行 `pnpm build`
- 若出现仓库既有问题，需明确区分是否由本次改动引入

## 风险控制

### 1. 行为理解风险

风险：

- 用户误以为规则可以同时命中多条

控制策略：

- UI 只展示“首条命中即停”的数组示例
- 文案明确“按顺序判断”和“只命中第一条”的语义

### 2. 校验错误风险

风险：

- 数组项字段缺失或表达式错误导致保存失败

控制策略：

- 所有输入统一转换为规则数组后再校验
- 校验与运行时使用同一份解析结果
