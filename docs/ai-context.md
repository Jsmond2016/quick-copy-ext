# AI Context

## 项目是什么

Quick Copy Ext 是一个面向 Web 异常反馈场景的浏览器扩展。

它的核心价值不是“抓包”本身，而是把分散在页面、接口和人工补充说明里的信息，整理成一份可直接复制给前后端协作方的标准化文本。

## 核心流程

用户侧的典型流程是：

1. 在页面上复现问题
2. 打开 popup
3. 查看当前页面信息和已捕获的接口请求
4. 勾选异常请求
5. 补充备注
6. 一键复制反馈内容

系统侧的典型流程是：

1. background 监听页面请求
2. 按 tab 维度缓存请求记录
3. popup 打开后读取当前 tab 的请求记录
4. popup 根据设置过滤请求
5. popup 组装复制文本并写入剪贴板

## 各层职责

### `src/pages/background`

负责：

- 捕获请求
- 缓存 tab 维度的请求记录
- 处理 popup 发起的 runtime 消息
- 管理 Apifox 缓存状态

这层偏“数据与消息基础设施”，通常不应该混入展示逻辑。

### `src/pages/popup`

负责：

- 展示页面摘要
- 展示和筛选请求记录
- 提供设置面板
- 展示状态和 toast
- 组织复制动作

这层偏“用户交互入口”，应尽量保持首屏轻量。

### `src/lib/quick-copy.ts`

负责：

- 共享类型
- 设置结构和默认值
- 文案组装
- 路径、时间、耗时等格式化
- 过滤逻辑
- Apifox 相关纯函数

这层是 popup 和 background 共享的核心能力层。

## 当前代码结构特点

### 1. 项目规模不大，但共享逻辑集中

虽然文件数量不多，但 `src/lib/quick-copy.ts` 承担了较多核心能力。

这意味着：

- 改动方便
- 但也更容易牵一发动全身

因此修改共享逻辑时，需要特别注意影响面。

### 2. popup 在走渐进式模块化

popup 最近完成了一轮职责拆分，开始从“大组件”向下面的结构过渡：

- 页面组件
- 展示组件
- runtime service
- 表单转换工具
- 轻量 hooks

这个方向是当前 popup 的推荐演进方向。

### 3. background 仍是相对集中且高风险的区域

background 涉及：

- 事件监听
- 缓存管理
- runtime message 协议
- 定时器和异步流程

这里的改动应尽量审慎，优先做最小变更。

## 更适合的改动方式

### 1. 渐进式重构

这个仓库更适合：

- 在现有结构上逐步下沉职责
- 先抽稳定边界，再考虑更高层抽象
- 优先让代码“清楚”，而不是“看起来高级”

不太适合：

- 一次性大搬家
- 短时间引入大量抽象层
- 把简单逻辑包装得过度复杂

### 2. 先保行为稳定，再谈形态优化

尤其是 popup 和 background 的协作链路中，应优先保证：

- 复制结果不被意外改坏
- 请求采集不丢
- 消息类型不失配
- 设置读写仍兼容

## 当前已知问题

### 1. lint 体系未完全对齐

`package.json` 中有 `lint` 脚本，但当前仓库缺少 ESLint 9 默认要求的 `eslint.config.*`，因此 `pnpm lint` 不能直接作为可靠通过标准。

### 2. TypeScript 检查存在一个已知背景页问题

当前 `pnpm exec tsc --noEmit` 会因为背景页里的 `Timeout` 类型问题报错。

如果你的任务不涉及该区域，不应把这个历史问题误判成当前改动引入的问题。

### 3. 文档体系仍在补齐中

已有文档主要集中在：

- popup 重构
- Apifox 性能

对于 AI 协作、代码规范、仓库级约束，当前正处于补基础设施阶段。

## AI 修改时要特别注意的点

### 1. 不要把重任务塞回 popup 首屏路径

涉及 Apifox、大对象处理、网络读取、全量解析等逻辑时，要优先考虑：

- 是否可以后台缓存
- 是否可以异步触发
- 是否可以延后执行

### 2. 不要随意改 runtime 协议

如果改了消息类型、返回结构、状态字段：

- popup 和 background 需要一起调整
- 类型定义需要同步更新
- 文档应补充说明

### 3. 不要让共享工具函数带上 UI 偏见

`lib` 里更适合放纯函数和共享结构，不适合放强耦合 popup 视图的逻辑。

## 推荐策略

面对这个仓库时，AI 更适合采用下面的策略：

- 先读 README 和相关文件，再动手
- 优先做最小改动
- 确有必要时再做结构优化
- 对 popup 改动优先按职责拆分
- 对 background 改动优先考虑兼容性
- 对共享逻辑改动优先评估影响范围
